# Запуск и работа агента

## Перед началом

Прочитай `AGENTS.md`, `README.md`, этот файл и `HANDOFF.md`. Учитывай последние указания пользователя. Не привязывай работу к конкретной модели, подписке или агентной среде. Общайся на русском. Не проси токен в чате, не читай `secrets/`, `*.env`, `*.pem`, не обращайся к Keychain/DPAPI для просмотра секрета. Секрет получает только локальный процесс при явно запрошенном действии.

Проверь папку и Python 3.11+. Не сканируй чужие каталоги. Сохраняй чужие изменения. Не устанавливай пакеты глобально: проект использует только stdlib. Отсутствие документа или команды объясняй по факту; не заявляй успешный запуск до проверки.

Перед инструкциями терминала определи ОС и среду фактического запуска проекта по доступным сведениям `platform`/ОС, shell и cwd. ОС интерфейса Codex сама по себе этого не доказывает. Если агент работает удалённо, в контейнере или WSL, не смешивай пути этой среды с терминалом компьютера человека: ручной `token-set` должен выполняться в той же установке проекта и среде, где затем работает CLI. Уточняй устройство/среду только при неоднозначности. Показывай человеку одну подходящую ветку команд; обе ветки ниже — справка для агента. Подставляй фактическую папку его проекта, а не путь автора или буквальный путь из примера.

Открытый исходный репозиторий: [DjEugeny/telegram-rich-messages](https://github.com/DjEugeny/telegram-rich-messages). Текущая версия — без отложки; непосредственный тест и его вид в Telegram подтверждены пользователем. Новый пользователь может прислать только ссылку в новый чат: помоги получить проект, прочитай документы репозитория и проведи настройку без доступа к прежней переписке. Объясни рабочий цикл обычными словами: материал → превью → правки → разрешение → публикация → проверка в Telegram. Команды и форматы данных остаются работой агента.

В начале предложи два независимых выбора: существующий или новый канал; существующий или новый бот. Учитывай уже сообщённый выбор и опыт человека; не повторяй пройденные шаги и не требуй создавать замену. Создание канала или бота предлагай как действие только в выбранной человеком ветке.

## Локальная демонстрация

1. Выполни `python3 tool.py demo` и при демонстрации Rich Media — `python3 tool.py demo-media`, затем `python3 tool.py build`; Windows — `py -3` вместо `python3`. Новые четыре черновика вымышленные, повтор команды не обновляет уже существующие записи.
2. Сам открой полученный `index.html` доступным инструментом среды. Если нужен HTTP, запусти `python3 tool.py serve --port 8765` и открой `http://127.0.0.1:8765/`.
3. Если автоматическое открытие недоступно, выдай точный абсолютный путь из результата сборки и инструкцию двойного щелчка; при работающем сервере — точную локальную ссылку.
4. Проверь изображение, текст, раскрытие блока, ссылку и переключение разделов. Для Rich Media проверь портреты без обрезки, порядок видео/изображений, controls и фактическое воспроизведение видео, цитату и custom fallback. Покажи пользователю, что данные вымышленные и токен не нужен. Демонстрационный custom ID не подтверждает доступность emoji в Telegram. Не переходи к реальной сети без намерения пользователя.

## Бот, токен, чат

Выясняй только отсутствующее: выбранный существующий или новый канал/группа, существующий или новый бот, свой или общий бот, тема. Для существующего бота переходи к проверке назначения и скрытому вводу токена человеком; если он уже умеет получать токен, не повторяй обучение BotFather. При выборе нового бота проведи через BotFather. Пользователь добавляет выбранного бота и выдаёт права в Telegram.

Целевой сценарий Ольги — публикации в её существующий публичный канал с автором от имени канала. Текущая live-проверка идёт на отдельном тестовом канале и боте; успех теста не подтверждает настройку рабочего канала. Отображение автора проверь вместе с человеком в Telegram, не считай его доказанным по ответу API.

Для скрытого ввода предложи **человеку** запустить в собственном терминале только подходящую для определённой среды последовательность.

macOS: `Cmd+Space` → поиск «Терминал» или `Terminal` → `Enter`. Дай `cd` с фактическим абсолютным путём папки проекта в кавычках, затем:

```sh
python3 tool.py token-set
```

По запросу `Токен бота (ввод скрыт):` человек копирует токен из BotFather, вставляет `Cmd+V` и нажимает `Enter`. Символы не отображаются — это ожидаемо.

Windows: меню «Пуск» → поиск `PowerShell` → обычный запуск без прав администратора. Дай `Set-Location -LiteralPath '…'` с фактической папкой проекта, затем:

```powershell
py -3 tool.py token-set
```

По запросу скрытого ввода человек вставляет токен через `Ctrl+V` и нажимает `Enter`; символы не отображаются. Не меняй ExecutionPolicy. Пути в командах экранируй по правилам выбранного shell.

Не запускай интерактивный ввод от имени человека и не проси вставить токен в чат. `getpass` должен скрывать ввод; если терминал этого не поддерживает, команда обязана остановиться без fallback с echo. На macOS сохранение идёт в Keychain через stdin, токен не включается в аргументы `security`. На Windows — DPAPI и ACL текущего пользователя. Ни логи, ни URL ошибок, ни HTML не должны раскрывать секрет. Ошибки API выводятся в очищенном виде.

В текущем коде защищённое хранилище Linux, включая WSL, не поддержано. Не обещай там сохранение токена и не предлагай plaintext-файл, переменную окружения или echo как замену. Локальная демонстрация без токена доступна; для доставки нужна поддерживаемая среда с проектом и её защищённым хранилищем.

Чат определяется по точному публичному `@username` или предоставленному проверенному числовому ID. Для общего бота не читай `getUpdates`, не меняй webhook. Не обещай получить историю сообщений Bot API. Для выделенного бота разовый `python3 tool.py discover --isolated-bot-consent` возможен только после явного согласования этого чтения, без webhook, без offset и подтверждения обновлений. Флаг фиксирует согласие технически, но не заменяет разрешение человека. В остальных случаях предложи передать ID, проверенный владельцем, или использовать публичное имя.

```sh
python3 tool.py check --chat @channel_username
```

`@channel_username` здесь пример: замени подтверждённым назначением, не исполняй буквально. Проверь `getMe`, `getChat`, `getChatMember`, доступ к нужной теме, право постить и редактировать. Preflight проверяет `can_send_photos` и `can_send_videos` по фактическим типам медиа поста. Для существующего сообщения проверь соответствие бот/чат/`message_id`. Проблему прав решает человек в Telegram; не обходи её другим ботом или чатом.

## Материал и версии

При неясном намерении спроси: «Это текст для поста в Telegram?». Сохраняй факты, смысл и авторский тон. Не добавляй обещания и декоративные сведения. Существенное переписывание согласуй. Принимай текст прямо или из указанного UTF-8 файла.

Принимай медиа из реально доступного вложения-пути, указанного локального файла или прямого HTTP(S) URL без редиректа. Если доступа к вложению нет, честно попроси доступный файл. Не имитируй получение вложения, не сканируй папки. Изображения до 10 MiB: PNG без interlace и JPEG 8-bit baseline grayscale/RGB с Huffman-кодированием. MP4 до 50 MiB: nonfragmented ISO-BMFF, один H.264/AVC `avc1` видеотрек и необязательный AAC `mp4a`. Неподдерживаемые варианты отклоняются явно; не обходи проверку переименованием. MP4 проверяется структурно, без декодирования каждого кадра. Метаданные, SHA256 и происхождение копии сохраняются в `media/`; у видео также размеры и длительность в секундах. Оригиналы и уже импортированные файлы не перезаписываются. Запуск не требует ffmpeg.

Обычные команды выполняй сам. Не отправляй новичка в терминал ради создания поста или сборки дашборда; исключение — скрытый `token-set`. Для текста создай черновик:

```sh
python3 tool.py create --title "Заголовок пользователя" --text "Текст пользователя"
```

Для указанного UTF-8 файла используй `--file "/точный путь/текст.txt"` вместо `--text`. Сохрани настоящий ID из результата. Повторяемые `--media`, `--image`, `--video` сохраняют общий порядок. По умолчанию новые файлы перед текстом (`--media-position before`), несколько объединяются в `collage`; доступны `--media-layout slideshow|separate` и `--media-position after`. Один файл — одиночный блок. JSON из `--blocks` задаёт полный порядок; дополнительные CLI-файлы добавляются к нему с выбранной стороны. Примеры — в `examples/README.md`.

Обновление только с `--media` сохраняет прежние блоки и добавляет новые файлы. `update POST_ID --text "Новый текст"` или `--file` заменяет прежний набор блоков текстом; чтобы сохранить медиа и изменить текст, возьми блоки из `show`, отредактируй их и передай полный `--blocks "/точный путь/блоки.json"`. Не записывай правки напрямую в файлы прежних версий.

Цитату оформляй `quote`, группы — `media_group` с `layout: collage|slideshow` и только image/video в items. Unicode emoji, включая ZWJ/skin tone/variation selectors, сохраняй без нормализации. Custom emoji — структурный узел с предоставленным человеком числовым `custom_emoji_id` и fallback-текстом: ID не угадывается по символу. Локально показывается доступный fallback без внешней анимации. Подчёркивание задаётся узлом `underline`; пользовательский HTML остаётся текстом. Не заменяй запрошенный custom emoji обычным emoji в payload молча.

Новый текст создаёт новую неизменяемую версию. Сгенерируй дашборд, открой его сам, проверь текст и локальные изображения. Данные от пользователя не должны исполняться как HTML. Подпись обязательна: «Приблизительный предпросмотр. Итоговый вид проверь в Telegram».

## Подтверждение отправки и правки

После актуального `check` подготовь операцию:

```sh
python3 tool.py review POST_ID --action send
```

Для согласованной правки используй `--action edit`. `POST_ID` — реальный ID из `list`/`show`. `review` получает подтверждённые сведения о боте/чате и связывает операцию с точной версией и хешем, назначением, ботом и прежним `message_id` для правки.

Перед правкой покажи различия между опубликованной и новой версиями: что добавлено, удалено или изменено, номера обеих версий и конкретный `message_id`, который останется прежним. Для подтверждения недостаточно показать только новый текст: человек должен видеть, какое существующее сообщение меняется.

Покажи конкретный текст/превью, номер версии, бота, название и ID чата, тему, действие и прежний `message_id`. Запрос пользователя на макет не равен разрешению публикации. Получи явное разрешение именно показанной версии именно в указанное назначение. После разрешения используй выданные CLI `operation_id` и fingerprint:

```sh
python3 tool.py execute OPERATION_ID --fingerprint CONFIRMATION_FINGERPRINT
```

Fingerprint связывает техническую операцию, но сам по себе не является человеческим разрешением. Изменение текста, версии, порядка/типов/группировки медиа, цитаты, custom ID, бота или назначения требует нового `review` и разрешения. Покажи состав и порядок медиа, их хеши и версию вместе с назначением. Не пересчитывай fingerprint вручную. Повтор execute той же операции не должен повторять сеть. Для сознательной второй публикации нужен новый явный запрос и отдельный `--new-publication`; обычная send опубликованного поста запрещена. Правка сохраняет `message_id`.

После ответа сообщи API-результат и сохранённый `message_id`, ссылку только при подтверждённой возможности её построить. Проверь обновление HTML. Попроси человека проверить вид текущей опубликованной версии в Telegram; только после его подтверждения выполни `python3 tool.py verify-visual POST_ID --confirmed`. Не ставь визуальную отметку по ответу API. Для проверки синтаксиса используй `verify-visual --help`: справка не вызывает Telegram.

## Голосовые поручения и границы редактора

Голос вводится в чате агентной среды. Дашборд — просмотр, выбор и фильтрация, без отдельного распознавания речи или текстового редактора.

Поручение: «Возьми файлы из этой папки. Сначала обложку, потом видео, затем второй и третий скриншот. Медиа над текстом. Пока только покажи превью». Агент сопоставляет названия/порядок с реальными файлами, сохраняет блоки полной версии, выполняет build и показывает результат. Неоднозначные файлы уточняет. «Поменяй второе и третье вложение местами» создаёт следующую версию, не изменяя старую.

Цитату можно обозначать словами: «Абзац от “…” до “…” оформи цитатой; после него обычный текст». Никаких JSON-терминов пользователь произносить не обязан. Агент создаёт quote и сохраняет полный набор блоков через update --blocks, чтобы не потерять медиа.

Обычные эмодзи: «Добавь красное сердце после последней фразы». Для custom emoji нужен точный ID; вставка символа в чат может сохранить только Unicode, потеряв связь с пакетом. Выбор/импорт пакетов по ссылке и каталог emoji в текущем CLI/UI отсутствуют. Полученный и проверенный ID можно сохранить структурным custom_emoji; локально виден доступный fallback, а доступность и анимация в Telegram проверяются отдельно. Предварительно публиковать пост ради записи ID не требуется.

## Если пользователь просит отложенную публикацию

В текущую версию она не входит. Скажи прямо: «Сейчас сервис готовит и публикует посты сразу после вашего разрешения. Отложка записана в план». Не предлагай дату как доступное действие и не запускай `schedule-review`/`schedule-execute`: новые сетевые операции отключены, даже с `--experimental`. Не заменяй Rich Message обычным альбомом или локальным таймером без отдельного решения.

Для обычной публикации не нужны direct messages канала, бесплатная цена, группа обсуждения, второй аккаунт и Controller Bot. Не веди новичка по этим веткам. Ему нужны канал, бот-администратор с правом публикации и скрытый ввод токена. Для существующего бота, обслуживаемого другим сервисом, не меняй webhook и не читай getUpdates; используй известный ID/username канала. Смена локального токена не подключает очередь Controller Bot.

План будущего решения — [docs/ROADMAP.md](docs/ROADMAP.md); наблюдения реального теста — [docs/controller-bot-check.md](docs/controller-bot-check.md). После этого возвращайся к подготовке, превью и непосредственной публикации.

### Старые экспериментальные записи

Сохраняй SQLite, proposal receipts, операции и версии. `schedule-list`, `schedule-recover` и `build` работают локально и не сверяют Telegram. Наличие proposal receipt не равно подтверждённому расписанию. Не удаляй записи, не объявляй предложение отсутствующим и не обходи активную операцию новой отправкой. При необходимости разбора изучи исторические [docs/scheduling.md](docs/scheduling.md) и `HANDOFF.md`; старые команды не являются разрешением продолжить опыт.

## Неизвестный результат и восстановление

`draft` — черновик; `sending` — выполнение начато; `published` — подтверждён API-успех; `error` — подтверждён отказ; `unknown` — неизвестно, принял ли Telegram операцию. `visual_verified` — отдельная отметка человека.

При таймауте, потере ответа или сбое процесса не повторяй отправку и не создавай заменяющую операцию. Вызови `python3 tool.py recover`: локальное восстановление читает устойчивые receipts, не отправляет сообщения. Не меняй активную `sending`; после подтверждённого завершения исполнителя она может перейти в `unknown`.

Если receipt содержит `message_id`, сообщение уже опубликовано: восстанови локальное состояние и HTML. Ошибка HTML не отменяет API-успех. Если локальная запись после успеха не завершилась, проверь receipts до любых дальнейших действий. Не удаляй сообщения ради исправления состояния.

При `unknown` человек проверяет назначение в Telegram. Привяжи проверенный ID с основанием:

```sh
python3 tool.py resolve OPERATION_ID --message-id VERIFIED_MESSAGE_ID --evidence "Пользователь проверил сообщение в указанном чате"
```

Не используй фиктивный ID. Если человек доказал отсутствие сообщения, зафиксируй основание: `python3 tool.py resolve OPERATION_ID --absent --evidence "Проверенное основание отсутствия"`. Устойчивый receipt с успешным результатом запрещает `--absent`: восстанавливай подтверждённый успех. После доказанного отсутствия новая публикация требует нового `review` и отдельного разрешения. Если доказательств нет, оставь `unknown` блокирующим. Гарантия exactly-once через сеть не обещается. Справка `resolve --help` не вызывает Telegram.

## Передача и перенос

Останавливай операции до копирования. Сохраняй `posts/`, `media/`, `data/` вместе; проверь повторное открытие проекта, локальные картинки и видео. На новой системе человек заново вводит токен. Не сбрасывай журнал операций, опубликованные версии или unknown для удобства. Не публикуй GitHub без прямого поручения. Перед завершением обнови `HANDOFF.md` фактическими командами, проверками и оставшимися ограничениями. Не переноси старые browser-pass на новую версию автоматически; при запрете `file://` не обходи policy, используй собственный синтетический HTTP fixture и дай человеку точный путь для ручного открытия.

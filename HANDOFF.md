# Текущее состояние для нового агента

Обязательная подготовка каждого поста: [docs/RICH-AUTHORING.md](docs/RICH-AUTHORING.md). Агент сам разбирает материал и применяет заголовки/подзаголовки 1–6, списки, цитаты, таблицы, details и inline-оформление по смыслу. `sendRichMessage` без структуры текста не является достаточной подготовкой. Перед разрешением сверяй `review.snapshot.formatting` с материалом и превью. Текст без настоящего непустого heading не проходит review/execute; прежние неотправленные операции без сводки требуют нового review и разрешения.

Локальная проверка этого изменения 19 октября 2026: 109 unittest OK, 26.162 s; node syntax, Python 3.11 syntax и diff check OK. Новые проверки используют fake API, настоящих отправок и чтения токена не было. Для существующих установок обнови исходники; прежние неотправленные review потребуют нового review и разрешения. Результаты прежних прогонов ниже относятся к прежним изменениям.

Проект опубликован: [DjEugeny/telegram-rich-messages](https://github.com/DjEugeny/telegram-rich-messages). Главная ветка — main. Репозиторий самодостаточен: Python 3.11+, стандартная библиотека, встроенные demo fixtures и шрифты с лицензиями.

## Если человек пришёл с одной ссылкой

Это первый запуск готового личного сервиса. Читай README.md, AGENTS.md и ONBOARDING.md, затем веди по шагам: запуск → пример по желанию или свой материал → выбранные канал и бот → скрытый ввод токена человеком → превью → разрешение → публикация → проверка Telegram.

Перед привязкой прочитай docs/TELEGRAM-SETUP.md: там разобраны существующий публичный/приватный канал, готовый/новый бот, уже добавленный администратор, получение действующего токена, открытие собственного терминала с реальной папкой и ожидаемым результатом. Не проси вырезать числа из ссылок: check --chat принимает целую ссылку. Не считай настройку законченной только потому, что бот уже в канале.

Последний полный рабочий прогон: 102/102 unittest OK, 25.245 s; node syntax и diff check OK. Локальные create/import/update тоже принимают целые ссылки, а без --chat сохраняют черновик без назначения и токена. Поддержаны progressive JPEG и округление длительности MP4 в пределах одного тика/1 ms. Четыре скачанных из Telegram оригинала успешно прошли импорт → черновик → build → повторную проверку, SHA256 сохранён. Проверка прав назначения остаётся через getMe/getChat/getChatMember; live-доступы при этой правке не использовались. Подробности — docs/RELEASE-STATUS.md.

Не возобновляй историю разработки и не пересказывай её пользователю. Старые планы не являются поручением нового человека. Не отправляй тестовый пост автоматически из-за обнаруженных доступов.

Среду запуска нужно определить заново. Продукт содержит ветки macOS и Windows; пути автора и ОС прежних проверок не задают платформу коллеги. Для remote/WSL отделяй среду агента от пользовательского компьютера. Прежние токены, боты и каналы не входят в исходники и не считаются настроенными в новой установке.

## История пользователя начинается со своих материалов

Для необязательного примера используй `preview-demo`. Он создаёт отдельную временную демонстрацию и не наполняет рабочую историю. Затем останови его и запусти рабочий `serve`; без сохранённых материалов рабочая история пустая. Не вызывай постоянные `demo`/`demo-media` в рабочей папке новичка.

Существующие посты/версии/receipts не удалять при переходе. Пользовательские данные исключены из Git; технические JSON и команды обрабатывает агент.

## Что проверено

Непосредственная публикация тестовой версии с видео, тремя изображениями, текстом и цитатой получила API-успех. Пользователь подтвердил выход/вложения, скриншот показал авторство канала и оформление; visual_verified сохранён. Это не настройка канала нового человека.

Опубликованный исходный коммит `8a6702a` был проверен настоящим чистым clone: demo-media, build, node --check и 86/86 unittest прошли. После добавления временного preview-demo полный прогон — 88/88 OK, 26.592 s; два новых теста проверяют изоляцию и удаление временных данных, сохранность личных постов и пустую рабочую папку при ошибке сервера. Node syntax прошёл. Прежние SQLite ResourceWarning остаются. Native Windows/DPAPI и playback в Telegram не имеют отдельного завершённого протокола; не выдавай старые проверки за текущую приёмку.

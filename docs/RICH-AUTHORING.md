# Обязательная подготовка текста в Rich Markdown

Сервис предназначен для структурированных Rich Messages. Агент получает обычный текст и вложения, сам выбирает подходящие поддержанные элементы и показывает готовое превью. Пользователь не обязан знать синтаксис или дополнительно просить оформление.

## Как разобрать материал

Сначала прочитай материал целиком. Найди основную тему, разделы, перечисления, последовательности действий, чужую речь, сравнения, справочные подробности и ссылки. Сохрани смысл, авторский тон, факты и порядок вложений. Затем собери канонические блоки, а не полотно абзацев с жирным началом.

| Смысл материала | Блок или inline-узел |
| --- | --- |
| Основная тема поста | `heading`, обычно level 1 или 2 |
| Разделы и подразделы | `heading` следующих уровней; доступны 1–6 |
| Обычная авторская речь | `paragraph` |
| Однородные пункты | `list`, ordered false |
| Шаги или последовательность | `list`, ordered true |
| Предоставленные слова другого человека | `quote` |
| Сравнение по общим признакам | `table` с headers и rows |
| Дополнительные подробности, которые можно свернуть | `details` с summary и вложенными blocks |
| Важная фраза внутри текста | `bold`, `italic`, `underline`, `strikethrough` по смыслу |
| Ссылка, фрагмент кода | `link`, `code` |
| Отдельное действие по ссылке | `button` |
| Изображение, видео, группа | `image`, `video`, `media_group` с collage/slideshow |

Используй возможности по содержанию, без обязательной квоты эффектов. Короткий текст может состоять из заголовка и абзацев. Длинный текст с разделами должен сохранить иерархию подзаголовков; реальные шаги — порядок; цитата — источник и исходный смысл. Не выдумывай чужую речь, данные таблиц, новые факты или custom emoji ID. Не прячь основной заголовок внутри `details`.

Это перечень поддержанных средств сервиса, а не обещание поддержки всего Telegram Rich Markdown. Неизвестный тип compiler отклоняет. Нужную неподдержанную возможность обозначь явно, не упрощай молча до обычного текста. Произвольный HTML и обход compiler запрещены.

## Настоящий заголовок и жирный абзац

`{"type":"paragraph","text":"**Зачем платить за презентацию?**"}` даёт жирный абзац. Он не становится заголовком от того, что стоит первым или совпадает с названием поста в истории.

`{"type":"heading","level":2,"text":"Зачем платить за презентацию?"}` компилируется в `## Зачем платить за презентацию?` и `<h2>…</h2>`. Для следующего подраздела подходит level 3. Выбор уровня должен отражать иерархию, а не желание изменить размер шрифта.

При подготовке используй полный `--blocks`, включая медиа. `--text/--file` удобен для сохранения исходного черновика, но не выполняет смысловой разбор иерархии, цитат, таблиц и подробностей. Не передавай Markdown-заголовки внутри paragraph в надежде на автоматическое преобразование.

## Проверка перед разрешением

1. Проверь блоки и экспорт `.md/.html` одной версии: heading соответствует заголовку, list — списку, quote — цитате; порядок медиа сохранён.
2. Покажи превью и краткое описание структуры человеку. Сверь текущую и опубликованную версии: новый локальный вариант ещё не означает изменение Telegram.
3. Выполни `review`. `snapshot.formatting` содержит `format=rich_markdown`, количество блоков, заголовки с уровнями и использованное inline-оформление. Эти данные входят в fingerprint операции.
4. Сопоставь сводку с исходным материалом. Наличие heading — проверяемый минимум; уместность подзаголовков, списков, цитат и остальных элементов проверяет агент. Сводка не является автоматической оценкой качества.
5. Получи разрешение конкретной версии и выполни `execute`. Если структура или правила изменились после review, заново покажи вариант и получи разрешение. Не обходи ошибку через прямой API, другую команду или классическую отправку.

`review` и `execute` блокируют текстовую публикацию без непустого heading верхнего уровня блоков. Медиа без текстовых блоков сохраняют свой rich-формат. Исходные черновики и старые версии остаются доступными; опубликованный receipt не требует повторной отправки после обновления правил.

Отправка использует `sendRichMessage` с `rich_message.markdown`, правка — `editMessageText` с тем же rich_message. Автоматического перехода на классическое сообщение нет. Размеры, шрифт и отступы Telegram могут отличаться от локального HTML; API-успех не подтверждает вид. Итоговую проверку выполняет человек в Telegram.

Синтаксис заголовков, списков, таблиц, цитат, details и media описан в [официальной документации Telegram](https://core.telegram.org/bots/api#rich-markdown-style).

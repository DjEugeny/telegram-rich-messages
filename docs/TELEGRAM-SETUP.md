# Подключение Telegram: инструкции для агента по шагам

Пользователь не обязан разбираться в ботах, токенах и ID. Этот документ задаёт конкретные действия и ожидаемые результаты. Выбирай только нужную ветку и выдавай **один текущий ручной шаг**, не весь документ сразу. После ответа/результата переходи дальше.

## Что выяснить без повторов

Основной реальный сценарий — уже существующий канал, часто публичный. Не начинай с предложения создать тестовый канал. Сначала спроси: «В какой ваш канал будем публиковать? Он уже существует?» Если ответ уже известен, не спрашивай заново.

Отдельно выясни бота: «Для этого канала уже есть бот, которого хотите использовать, или создадим нового?» Если пользователь уже выбрал существующего бота, не предлагай замену. Попроси его @username; название профиля может отличаться.

Держи отдельно четыре факта: выбран канал; выбран бот; бот администратор канала; токен сохранён **в этой установке**. Один факт не доказывает остальные. Ответ «бот уже добавлен» закрывает только шаг администратора. Даже опытному владельцу существующего бота нужна конкретная инструкция скрытого ввода в текущую установку, если сохранение ещё не подтверждено.

Показать настройки/сохранить токен/проверить подключение можно в ходе согласованной настройки. Публикацию ни один из этих шагов не разрешает.

| Ситуация | Следующий шаг |
| --- | --- |
| Канал существует, бот выбран и уже администратор | Получить ссылку канала, затем действующий токен и показать точную инструкцию его скрытого ввода |
| Канал существует, бот есть, но ещё не добавлен | Помочь добавить выбранного бота администратором, затем сохранить токен |
| Канал существует, бота нет | Создать бота через BotFather по выбору пользователя, добавить в существующий канал |
| Канала нет | Помочь создать канал только после выбранной пользователем ветки; затем отдельно выбрать бота |
| Бот используется другим сервисом | Использовать текущий токен; не отзывать его, не менять webhook, не читать updates |

## 1. Ссылка существующего канала

### Публичный канал

Готовая инструкция для пользователя:

> Откройте нужный канал в Telegram. Нажмите его название сверху — откроется информация о канале. Найдите «Ссылка» или «Публичная ссылка» вида https://t.me/channel_name. Скопируйте её и пришлите сюда целиком. Если знаете @username канала, можно прислать его. Публикации выбирать и менять не нужно.

Если поле/кнопки не находятся, спроси, какой клиент Telegram открыт, или попроси скриншот карточки канала. Не придумывай точную подпись кнопки, если интерфейс отличается. Разбирай целую ссылку сам; не проси вручную дописывать @ или извлекать числа.

### Приватный канал, в котором есть публикации

Готовая инструкция для Telegram на компьютере:

> Откройте сам канал и найдите любой уже существующий пост. Нажмите правой кнопкой по тексту поста или по его карточке. В меню выберите «Копировать ссылку на сообщение» — иногда пункт называется «Копировать ссылку». Вставьте ссылку сюда целиком, ничего из неё вырезать не нужно. Сам текст поста присылать или пересылать не требуется.

На телефоне используй долгое нажатие по посту и соответствующий пункт меню, уточняя текущий экран при отличиях. Не направляй человека в обсуждение или «Сообщения каналу». Не проси публиковать тестовый пост, если существующий подходит.

Агент передаёт всю ссылку `https://t.me/c/…/…` в `check --chat`; CLI извлекает назначение локально и проверяет канал через Bot API. Содержимое выбранного поста не читается и не меняется. Ссылка-приглашение `t.me/+` или `joinchat` для этого не подходит: объясни, что нужна ссылка именно **на сообщение**, и повтори путь меню. Не проси «пришли число после /c/».

### Приватный канал без публикаций

Сначала уточни, есть ли хотя бы один пост. Не проси ссылку на несуществующее сообщение и не заставляй делать приватный канал публичным.

Если выбран новый/выделенный бот, у него нет webhook и пользователь согласовал одно чтение, агент может получить ID из события добавления бота в администраторы через `discover --isolated-bot-consent`. Перед этим объясни одним предложением: «Можно один раз проверить событие добавления нашего отдельного бота, чтобы определить канал без публикации?» Выполняется ровно одно согласованное чтение; пустой результат не разрешает повтор. Отсутствие события не означает отсутствия бота.

Для общего бота этот путь не предлагать. Тогда объясни выбор: владелец может предоставить уже известный ID из настроек своего сервиса либо **сам** разместить согласованное короткое сообщение в канале и скопировать его ссылку по инструкции выше. Публиковать служебный пост без решения пользователя нельзя. Если ни один путь не подходит, останови только привязку и согласуй следующий шаг; не выдумывай ID и не проси секреты другого сервиса.

## 2. Уже существующий бот: найти текущий токен

При необходимости объясни одним предложением: «Токен — секретный ключ вашего бота; вы один раз сохраните его программе на своём компьютере через скрытый ввод». Не называй этот процесс отправкой токена агенту.

Если человек уже скопировал действующий токен, переходи сразу к инструкции собственного терминала ниже. Наличие опыта не повод её пропустить.

Если нужна помощь:

> В Telegram откройте официальный @BotFather: [открыть BotFather](https://t.me/BotFather). Отправьте ему /mybots. Выберите нужного бота по @username. Найдите «API Token» либо страницу токена этого бота. Скопируйте показанный действующий токен кнопкой Copy или обычным копированием. В этот чат его не вставляйте. Пока напишите только «токен скопирован».

Кнопки BotFather могут меняться. Если нужного пункта не видно, попроси описание меню или скриншот **без показанного токена**. Если бота нет в /mybots, выясни, с какого Telegram-аккаунта он создавался и кто владелец; список администраторов канала не даёт владение ботом. Не требуй доступа к секретным файлам другого сервиса.

Не называй `/token` способом без последствий показать прежний токен. Официальная документация описывает эту команду как генерацию нового токена. Для бота, обслуживающего другой сервис, **не предлагай генерацию/перевыпуск по умолчанию**. Не нажимай Revoke/Revoke current token. Ротация — отдельное решение владельца, не обычный шаг подключения.

## 3. Если пользователь выбрал нового бота

> Откройте [@BotFather](https://t.me/BotFather) и отправьте /newbot. Сначала задайте отображаемое имя, затем уникальное имя пользователя, заканчивающееся на bot. Если имя занято, выберите другое. Когда бот создан, пришлите сюда только его @username. Токен оставьте в BotFather — дальше сохраним его через скрытый ввод.

Полученный токен вводится тем же способом ниже. Не проси создавать нового бота, если человек уже выбрал существующего.

## 4. Добавить бота администратором

Если пользователь уже сообщил, что выбранный бот администратор, не проси добавлять его заново. Права затем проверит check.

Иначе дай текущий шаг:

> Откройте выбранный канал. Нажмите название сверху и откройте «Управление каналом» / «Изменить», затем «Администраторы» → «Добавить администратора». Найдите бота по точному @username, который мы выбрали, и выберите его. Оставьте право «Публикация сообщений» / «Публиковать сообщения» и сохраните. Когда сохраните, напишите «бот добавлен».

Если права объединены в «Управление публикациями», попроси раскрыть группу и убедиться, что публикация включена. Названия зависят от клиента; при другом экране запроси его вид без секретов. Не включай несвязанные права изменения профиля, назначения администраторов, блокировок, историй или трансляций. Не обещай иметь возможность назначить администратора, если у человека нет такого права; тогда требуется владелец канала.

## 5. Передать токен в систему: собственное окно терминала

Этот шаг нужен и для нового, и для существующего бота, включая уже добавленного в канал. Человек вводит токен локальному процессу, **не агенту и не в чат**.

Сначала определи среду и фактическую папку установки. Выбери одну ветку. Сформируй команды с реальным абсолютным путём, правильным shell-экранированием и проверенной командой Python. Не давай человеку буквальные «ПАПКА_ПРОЕКТА», POST_ID или примеры путей автора.

Не запускай token-set сам и не оставляй его якобы ожидающим ввода в фоновом/непонятном терминале. По умолчанию человек открывает своё системное приложение «Терминал» или PowerShell по явной инструкции. Если уже есть открытый служебный терминал с сервером, для токена нужно **новое окно**; работающий сервер останавливать не требуется.

### macOS

Первый текущий шаг:

> Нажмите Cmd+Space, напишите «Терминал» и нажмите Enter. Откроется отдельное окно. Напишите «открыл», если оно появилось.

После подтверждения дай две готовые строки: `cd` в **фактическую** папку проекта в кавычках, затем `python3 tool.py token-set`. Если используется другой проверенный Python, подставь его. Объясни: строки вставляются по очереди, после каждой нажимается Enter.

Следующий шаг, только после появления запроса:

> Должна появиться строка «Токен бота (ввод скрыт):». Теперь скопируйте действующий токен из BotFather, вернитесь в это окно Терминала, вставьте Cmd+V и нажмите Enter. Символы, точки или звёздочки могут вообще не появляться — это нормально. Не вставляйте токен до появления этой строки.

### Windows

Первый текущий шаг:

> Нажмите «Пуск», напишите PowerShell и откройте его обычным запуском, без прав администратора. Откроется отдельное окно. Напишите «открыл», если оно появилось.

После подтверждения дай две готовые строки: `Set-Location -LiteralPath '…'` с **фактической** папкой и корректным экранированием, затем `py -3 tool.py token-set` (либо заранее проверенный `python`). По очереди Enter после каждой. Не меняй ExecutionPolicy.

После появления «Токен бота (ввод скрыт):» человек копирует действующий токен из BotFather, вставляет **Ctrl+V** в PowerShell и нажимает Enter. Отсутствие видимых символов ожидаемо. Не предлагай Cmd+V на Windows или Ctrl+V в инструкции для macOS.

### Ожидаемый результат и ответ человека

Покажи заранее, что будет после успешного ввода:

```json
{
  "token": "сохранён в защищённом хранилище"
}
```

Заверши этот шаг понятным запросом:

> Пришлите только этот результат «сохранён в защищённом хранилище» или скриншот нижней части Терминала/PowerShell после завершения команды. Сам токен и окно BotFather с ним не показывайте.

Если вместо результата ошибка, попроси её текст без секрета и разберись с текущим шагом. «Не найден tool.py» означает неверную папку, а не необходимость нового бота. «Скрытый ввод недоступен» требует подходящего интерактивного терминала, а не echo/plaintext. Не говори «доступ уже настроен» по факту запуска дашборда.

При remote/контейнере/WSL сначала выясни, где установлена поддерживаемая локальная версия: пути агента нельзя выдавать как пути компьютера пользователя. Сохранение токена и CLI доставки должны работать в одной установке.

## 6. Проверка привязки агентом

После подтверждения сохранения и получения полной ссылки агент выполняет `check --chat 'ССЫЛКА_КАНАЛА_ИЛИ_ПОСТА'` с реальным значением. Ссылка разбирается локально; запросы getMe/getChat/getChatMember проверяют бота, назначение и права. Updates общего бота не читаются.

Сравни возвращённый @username бота с выбранным человеком, тип и название канала — с его выбором. Если проверка вернула другого бота, другое назначение, группу вместо канала или нет прав, **не публикуй**; объясни проблему и вернись к соответствующему шагу. Не заменяй выбранного бота сам.

Успешный ответ человеку:

> Подключение готово: бот @… может публиковать в канале «…». Теперь подготовим ваш пост и покажем превью. Отправка будет только после вашего разрешения.

Не отправляй тест автоматически. Если человек просит тест, подготовь его точный текст/версию/назначение, покажи и получи разрешение. Не проси вручную преобразовывать ссылки/ID и не объясняй API/числовые диапазоны новичку.

## Источники для проверки агентом

Кнопки сверяй с текущим клиентом. Технические источники — для агента, их не нужно прикладывать к каждому бытовому шагу пользователя: [BotFather](https://core.telegram.org/bots/features#botfather), [форматы ссылок](https://core.telegram.org/api/links#message-links), [преобразование ID](https://core.telegram.org/api/bots/ids). Проверены 18 октября 2026. Эти ссылки не заменяют конкретную инструкцию «что открыть, куда нажать, какой результат прислать».

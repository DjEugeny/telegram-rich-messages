# Технический статус версии

## Реальные медиа и назначение локального черновика, 19 октября 2026

Устранены два отказа на скачанном из Telegram материале: три progressive JPEG
510×907 отклонялись из-за профиля SOF0-only; MP4 AVC/AAC 604×1080 отклонялся
из-за строгого равенства mdhd и суммы stts. В видео: 183997 против 183998 при
timescale 30301; в аудио: 268435 против 268436 при timescale 44100.
Это расхождение на один тик, а не на кадр. Теперь разрешён один тик с верхней
границей 1 ms; число samples, ненулевые интервалы, offsets и NAL проверяются
как прежде. Заголовки файла не переписываются.

Добавлен stdlib-проверяющий progressive Huffman JPEG по ITU-T T.81 Annex G:
первые/уточняющие проходы, spectral selection, порядок уровней, EOB runs,
restart и padding, с ограничением памяти и работы. Импорт и повторная
проверка используют один профиль; оригинальные JPEG сохраняются без конвертации.
Ограничения: 8-bit grayscale/RGB, 128 scans/100 млн позиций коэффициентов.
PNG/interlace, JPEG arithmetic/lossless и иные видеокодеки остаются вне профиля.

`create`/`import`/`update --chat` теперь разбирают те же полные ссылки, что и
`check`, до импорта файлов и открытия Store. Сохранение без `--chat` доступно
без токена/сети; права и фактический адресат проверяются на этапе review.
Безопасные ошибки медиа показывают причину вместо общего «детали скрыты».

Проверка на четырёх исходных файлах: импорт CLI → сохранение черновика с
целой приватной ссылкой → build превью → validate_media. Все четыре приняты;
SHA256 оригиналов и копий совпадают; исходники не менялись. Проверка выполнена
во временной папке с заблокированной load_api; ни один пост не отправлялся.
В репозиторий добавлены только синтетические fixtures, без пользовательских медиа.

Новые регрессии: два JPEG внешнего encoder, DC/AC refinement, EOB и restart,
неверный порядок scans/обрыв/padding; MP4 ±1 тик против ±2 и большого
расхождения; локальные черновики/версии без токена, ссылки create/import/update,
отказ плохой ссылки до импорта/Store, безопасная диагностика повреждения.
Временный корпус 48 JPEG (L/RGB, разные размеры/качество, restart) также принят.
Независимое локальное декодирование всех четырёх оригиналов через ffmpeg
успешно, stderr пустой; для MP4 сохранена исходная timebase (`-enc_time_base:v demux`).
Это диагностический инструмент разработчика, новой зависимости сервиса нет.
Полный текущий рабочий прогон: **102/102 unittest OK, 25.245 s**, включая
параллельные правки обработки текста в этой рабочей папке. Существующие
ResourceWarning SQLite остаются. Визуальная проверка Telegram/браузера и
native Windows в этой правке не проводились.

## Подключение существующих каналов и ботов, 18 октября 2026

Добавлено обязательное пошаговое руководство docs/TELEGRAM-SETUP.md. Раздельно учитываются выбранный канал, выбранный бот, его администраторство и сохранение токена в текущей установке. Основной сценарий — существующий реальный канал. Публичному каналу достаточно ссылки из карточки; приватному с постами — целой ссылки из контекстного меню сообщения. Для пустого приватного канала предусмотрена отдельная ветка без несуществующего поста и без несогласованной публикации. Общий бот не подвергается чтению updates, смене webhook или ротации токена.

Инструкции токена теперь требуют собственного нового окна Terminal/PowerShell, фактической папки, двух конкретных команд, ожидания строки скрытого ввода, подходящей клавиши вставки и точного ожидаемого JSON. Человек присылает только результат сохранения или безопасный скриншот после завершения. Агент не запускает якобы ожидающий token-set и не пропускает этот шаг для бота, уже добавленного в канал. BotFather /token описан как генерация, а не безопасный просмотр текущего токена.

CLI check --chat принимает публичную ссылку канала/поста и приватную ссылку сообщения целиком. Новый normalize_chat_reference разбирает их локально, проверяет хост/формат и диапазон channel ID, затем использует обычные getMe/getChat/getChatMember. Содержимое сообщения не читается. Ссылки-приглашения, комментарии/темы, чужие хосты и credential-bearing URL отвергаются без отражения секретных строк; CLI делает это до чтения токена и создания Store.

Проверки: **91/91 unittest OK, 26.557 s**; node --check и git diff --check OK. Три новых теста покрывают целые публичные/приватные ссылки и границы преобразования ID, отказ опасных/неподходящих ссылок без токена и файлов, а также check с проверкой прав/сохранением нормализованного назначения на fake API. Пять стартовых документов проверены на целостность локальных ссылок и code fences. Прежние SQLite ResourceWarning остаются. Новых live-вызовов Telegram, ввода токена и визуального прохода клиента в этой правке не было.

## Обновление первого запуска, 18 октября 2026

README, ONBOARDING, AGENTS и HANDOFF теперь описывают готовый сценарий: запуск, необязательный пример/свой пост, выбранные канал и бот, скрытый ввод токена, превью и разрешение публикации. История разработки вынесена в docs/development/; она не входит в обязательное чтение при первом запуске. Агент не перечисляет планы и отсутствующие функции по своей инициативе и не объявляет сервис предназначенным только для ОС своего хоста.

Добавлен `preview-demo --port PORT`: отдельный TemporaryDirectory с пятью вымышленными постами, собственными SQLite/media/web и loopback-сервером. Рабочий root не открывается как Store; токен не читается. Штатная остановка/ошибка очищает временную папку. Постоянные demo/demo-media сохранены для совместимости, но исключены из сценария новичка. Старые данные существующих пользователей автоматически не удаляются.

Полный прогон: **88/88 OK, 26.592 s**, `node --check web/app.js` OK. Два новых теста проверяют изоляцию от существующего личного поста, отсутствие загрузки токена, очистку после остановки, маркировку демо и пустую рабочую папку после ошибки сервера. ResourceWarning SQLite остаются. Нового визуального browser-прохода нет; banner и данные проверены на уровне собранного HTML. Результат не является native Windows-приёмкой.

Дополнительно реально запущен `python3 tool.py preview-demo --port 8771`: HTTP 200, встроенные данные содержат 5 draft-постов, маркировку «Демонстрация» и пояснение об отсутствии записей в личной истории. Процесс штатно остановлен Ctrl+C. Это HTTP smoke, не проверка рендеринга браузером.

## Что изменено при закрытии

- README, ONBOARDING, AGENTS, PRODUCT и начало HANDOFF описывают текущий объём. Новичку не нужны настройка direct messages, цена, второй аккаунт, Controller Bot или хостинг.
- CLI отказывает новым `schedule-review` и выполнению `reviewed`-операций `schedule-execute` до чтения токена и сети. Исторические guards, completed receipts и offline-восстановление сохранены. Внутренний `scheduling.py` оставлен для истории, не для обхода запрета.
- В дашборде старые операции показаны как история эксперимента; у остальных постов раздел скрыт. В проекте без таких записей нет фильтров отложки. Версии, медиа, SQLite и receipts не удалялись.
- [Опыт Controller Bot](controller-bot-check.md) записан с контролями: обычный текст принят, обычная пересылка принята, наш Rich Message в редактор не попал. Причина внутри сервиса неизвестна; общий вывод обо всех Rich Messages не делается.
- Дашборд autopilot обновлён. Старое состояние сохранено в `.autopilot/2026-10-18-telegram-scheduling--wip/state-at-deferral.json`; исходный G4 отложки не превращён в успешный. 14 незакрытых требований перенесены в deferred по решению пользователя; 22 done сохраняют свои исторические доказательства.

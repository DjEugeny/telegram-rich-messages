# ADR 0003. Стандартная библиотека и ограниченный набор изображений v1

## Контекст

Проект должен переноситься между macOS и Windows и работать на Python 3.11+ без установки пакетов. При этом импорт обязан проверять тип, размеры и целостность изображения, ограничивать размер 10 MB и сохранять локальную копию без изменения оригинала. Полная поддержка вариантов PNG/JPEG при таком ограничении стека не заявлена.

Основание: `spec.md`, S1 и S5; `manifest.md`, R02, R04, R05 и ограничение D01.

## Решение

Использовать только стандартную библиотеку Python. Для v1 принимать PNG без interlace и 8-bit baseline JPEG с Huffman-кодированием в grayscale/RGB. Interlaced PNG, progressive/lossless/arithmetic JPEG и другие неподдерживаемые варианты отклонять понятной ошибкой. Не выдавать проверку сигнатуры за полную проверку читаемости и целостности; повреждённый Huffman stream также должен отклоняться.

Ограничение D01 явно отражать в пользовательской документации. Не обещать поддержку любого файла с расширением `.png` или `.jpg` и не преобразовывать неподдерживаемый оригинал скрытно. Проверенные материалы копировать под уникальными именами в `media/`, сохраняя MIME, SHA256 и происхождение. Для URL загружать только указанный прямой HTTP(S)-ресурс.

## Почему (альтернативы + почему отвергнуты)

Внешняя библиотека декодирования могла бы расширить форматную совместимость, но потребовала бы установки зависимостей вопреки выбранному контракту простого запуска. Полный собственный декодер всех вариантов PNG/JPEG существенно расширил бы объём и сложность v1. Поэтому выбран явно ограниченный форматный профиль.

Приём по расширению или одной сигнатуре был бы проще, но не выполнял бы требование обнаруживать нечитаемые и повреждённые данные. Обещание полной поддержки PNG/JPEG при фактическом ограничении профиля вводило бы пользователя в заблуждение. Автоматическое преобразование не выбрано: в согласованной спецификации предусмотрены проверка и копирование оригинала, а не отдельный конвейер конвертации.

## Последствия

Для запуска не нужен менеджер пакетов, но часть корректных изображений PNG/JPEG будет отклоняться. Пользователю может потребоваться заранее сохранить изображение в поддерживаемом варианте. Это компромисс переносимости и объёма реализации, а не утверждение о некорректности неподдерживаемого файла. Расширение форматов потребует отдельного решения о зависимостях либо о развитии валидатора и его проверок.

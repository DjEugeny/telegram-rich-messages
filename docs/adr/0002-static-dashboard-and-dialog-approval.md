# ADR 0002. Статический дашборд и разрешение доставки в диалоге

## Контекст

Инструмент нужен для локальной подготовки произвольных постов агентом, с возможностью остановиться на черновике. Просмотр должен работать без Telegram и внешних ресурсов. Макет не является разрешением публикации, а локальный HTML не гарантирует совпадения с видом сообщения в Telegram.

Основание: `spec.md`, S2–S4; `manifest.md`, R08–R15, R19, R23.

## Решение

Генерировать один статический `index.html` из SQLite с разделами «Пост» и «История». Использовать локальные CSS, JavaScript, шрифты и изображения; поддерживать `file://` и loopback-сервер с ограниченным набором доступных ресурсов. Не давать серверу HTTP API записи и не размещать кнопку отправки в дашборде.

Один канонический JSON блоков компилировать в Rich Markdown и безопасный HTML. Пользовательские строки экранировать или вставлять через `textContent`; произвольный HTML не исполнять. Предпросмотр сопровождать подписью «Приблизительный предпросмотр. Итоговый вид проверь в Telegram».

Подготовку и обсуждение правок вести через агента. Перед доставкой выполнять `review`, показывать человеку конкретную версию, назначение, бота и предыдущую публикацию. Только после явного разрешения выполнять `execute` с operation ID и одноразовым confirmation fingerprint. Изменение согласованного состояния требует нового review. Визуальное подтверждение фиксировать отдельно после сообщения человека.

## Почему (альтернативы + почему отвергнуты)

CMS или приложение с постоянно работающим backend добавили бы инфраструктуру вне установленного масштаба локального инструмента. Статический экспорт позволяет просматривать материалы офлайн, а ограниченный сервер не открывает исходники, SQLite и секреты.

Кнопка отправки в интерфейсе объединила бы просмотр макета с внешним действием, хотя требуется отдельное разрешение конкретного snapshot. Публикация через диалог и CLI делает эту границу явной. Независимое редактирование HTML и Rich Markdown создало бы два расходящихся источника, поэтому оба представления строятся из общих блоков.

## Последствия

После изменения состояния дашборд необходимо пересобирать. Он служит просмотром и историей, а запись и доставка выполняются через CLI и агента. Для отправки нужен отдельный шаг согласования; автономный просмотр не требует токена. Приёмка внешнего вида остаётся отдельным действием в Telegram и не выводится из результата API или локального превью.

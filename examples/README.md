# Примеры и канонические блоки

Все примеры локальные. Создание и обновление не отправляют сообщения. Пути в командах замените на реальные доступные файлы; `POST_ID` — результат `create`/`list`.

## Демонстрации без токена

```sh
python3 tool.py demo
python3 tool.py demo-media
python3 tool.py build
python3 tool.py serve --port 8765
```

Windows: `py -3` вместо `python3`. `demo` создаёт один прежний вымышленный пост с PNG, списком, details и URL-кнопкой. `demo-media` добавляет четыре отдельных вымышленных черновика: шесть изображений 320×400 (4:5), одно 300×400 (3:4), видео плюс три изображения 225×400 (9:16), одно 320×400 с цитатой. Медиа идут перед текстом. Встроенный MP4 — 96×160 (3:5), одна секунда, H.264 без звука; его пропорция отличается от фотографий смешанной группы. Повторный запуск не добавляет версии/файлы и не меняет уже существующие примеры. Старый `demo` и пользовательские посты не обновляются.

PNG генерируются стандартной библиотекой. `fixtures/avc-96x160.mp4.base64` содержит собственное настоящее синтетическое AVC-видео: base64 восстанавливается без внешних программ. ffmpeg не требуется для демонстрации и запуска. Custom ID `1234567890123456789` в демо вымышленный: он иллюстрирует структуру, не годится как доказанный рабочий ID для публикации.

## Медиа через CLI

```sh
python3 tool.py create --title "Вымышленный анонс" --text "Материал для обсуждения" --video "/путь/ролик.mp4" --image "/путь/первый.png" --media "/путь/второй.jpg"
python3 tool.py import --title "Локальная серия" --file "/путь/текст.txt" --media "/путь/первый.png" --media "/путь/второй.jpg" --media-layout slideshow
python3 tool.py create --title "Отдельные блоки" --text "Текст над файлами" --image "/путь/первый.png" --image "/путь/второй.png" --media-layout separate --media-position after
python3 tool.py update POST_ID --media "/путь/ещё.png" --media-position after
```

`create` и `import` создают пост одинаково. Повторяемые `--media`, `--image`, `--video` сохраняют общий порядок, даже когда смешаны. `--media` определяет PNG/JPEG/MP4 по содержимому; `--image` ограничен изображениями, `--video` — MP4. Один новый файл — одиночный блок; несколько по умолчанию — `media_group` с `layout: collage`. `slideshow` создаёт листаемую группу, `separate` — несколько последовательных одиночных блоков. Расположение новых файлов по умолчанию `before`, доступно `after`.

В `--text/--file` пустая строка начинает новый абзац. Строки `- пункт` образуют маркированный список; `1. пункт`, `2. пункт` — нумерованный. Длинное тире `—` остаётся авторским текстом и не превращается в список. Для других структурных блоков передайте `--blocks`.

`update` без `--text`/`--file`/`--blocks` сохраняет старые блоки и добавляет новые файлы. С `--text` или `--file` прежний набор блоков заменяется текстовым. Для изменения текста с сохранением вложений возьмите полный массив `blocks` из `show`, измените текст и передайте `--blocks`. Дополнительные CLI-файлы с `--blocks` вставляются с выбранной стороны; внутренний порядок JSON сохраняется. Каждая правка добавляет неизменяемую версию.

## Текст, цитата и inline JSON

Сохраните следующий массив UTF-8 в `блоки.json`. Он пригоден для локального `create --blocks`; custom ID здесь намеренно демонстрационный, его нельзя считать подтверждённым для доставки.

```json
[
  {"type": "heading", "level": 2, "text": "Вымышленная мастерская"},
  {"type": "quote", "text": "Первый абзац цитаты.\n\n**Выделенная мысль** во втором абзаце."},
  {"type": "paragraph", "text": [
    "Unicode без замены: 👩🏽‍💻 ❤️ 🏳️‍🌈. ",
    {"type": "underline", "text": "Подчёркивание"},
    " и ",
    {"type": "strikethrough", "text": "зачёркивание"},
    ". Демонстрационный custom: ",
    {"type": "custom_emoji", "text": "⭐", "custom_emoji_id": "1234567890123456789"}
  ]},
  {"type": "list", "items": ["Первый пункт", ["Второй с ", {"type": "bold", "text": "выделением"}]]}
]
```

```sh
python3 tool.py create --title "Вымышленная мастерская" --blocks "/точный путь/блоки.json"
```

`heading`, `paragraph`, `quote` и элементы `list.items` принимают прежнюю строку с inline subset bold/italic/code/HTTP(S)-URL либо список строк и структурных узлов. `text` и `custom_emoji` имеют строковое `text`; `bold`, `italic`, `underline`, `strikethrough`, `code`, `link` принимают строку либо список узлов. `link` дополнительно требует `url` HTTP(S); вложенные ссылки запрещены. `custom_emoji_id` — строка из 1–32 цифр, fallback `text` — непустой текст до 64 символов без перевода строки. Inline-вложенность ограничена 16 уровнями. ID предоставляет человек; по обычному символу он не угадывается. Unicode ZWJ/skin tones/variation selectors сохраняются исходной последовательностью.

`quote` сохраняет абзацы и выделения, компилируется в Rich Markdown с `> ` на каждой строке и semantic `blockquote` локально. Custom emoji компилируется в `![fallback](tg://emoji?id=ID)`, локально — доступный fallback без внешней анимации. `underline` генерирует `<u>…</u>`, `strikethrough` — `~~…~~`. Введённый HTML остаётся экранированным текстом; опасные ссылки отклоняются. Наличие fallback не разрешает молча заменить запрошенный custom emoji в API payload.

## Группа с настоящими метаданными

Не придумывайте `path`/`sha256`/размеры/длительность. Импорт возвращает их после проверки и копирования. Пример для агента из корня проекта: сначала замените два исходных пути реальными, затем выполните в Python; он только создаёт локальный JSON `блоки-медиа.json`.

```python
import json
from pathlib import Path
from core import import_media

root = Path.cwd()
sources = [Path("/точный путь/ролик.mp4"), Path("/точный путь/портрет.png")]
items = []
for source in sources:
    metadata = import_media(root, source)
    items.append({
        **metadata,
        "type": "video" if metadata["mime"] == "video/mp4" else "image",
        "alt": "Вымышленный пример",
    })
blocks = [
    {"type": "media_group", "layout": "collage", "items": items},
    {"type": "heading", "level": 2, "text": "Медиа перед текстом"},
    {"type": "quote", "text": "Сначала посмотрим, затем обсудим."},
]
(root / "блоки-медиа.json").write_text(
    json.dumps(blocks, ensure_ascii=False, indent=2), encoding="utf-8"
)
```

Затем: `python3 tool.py create --title "Локальная группа" --blocks "блоки-медиа.json"`. Для слайд-шоу смените `layout` на `slideshow` до создания новой версии. В `items` допустимы только `image`/`video`, от 2 до 50, порядок сохраняется. Для одного файла используйте сам leaf. Это локальная граница группы; общий Rich Message ограничен 50 медиа/500 блоками/16 уровнями вложенности.

`image` хранит относительный `path: media/…`, MIME `image/png|image/jpeg`, SHA256, `width`, `height`, `source`, `alt`. У `video` MIME `video/mp4` и дополнительно положительная конечная `duration` в секундах. `import_media(root, source)` определяет тип, `import_image` и `import_video` ограничивают его явно. `source` фиксирует происхождение, но в Bot API не отправляется.

## Границы файлов и превью

Изображения до 10 MiB: PNG без interlace и JPEG 8-bit baseline grayscale/RGB с Huffman-кодированием. Progressive/lossless/arithmetic JPEG и PNG с interlace отклоняются. PNG проверяется по CRC/zlib/фильтрам/строкам/палитре. JPEG — по структуре, таблицам, Huffman-потоку и числу DCT-блоков, без восстановления RGB. Сумма сторон до 10000, отношение сторон до 20:1. `baseline-16x16.jpg.base64` — тестовый JPEG собственного градиента, созданный macOS `sips`; sips для запуска тестов не нужен.

MP4 до 50 MiB: nonfragmented ISO-BMFF с поддерживаемым brand, один видеотрек H.264/AVC `avc1`, необязательный AAC `mp4a` аудиотрек, размеры каждой стороны 1–8192. Проверяются обязательные ftyp/moov/mdat, metadata, sample tables, timing, offsets внутри mdat, codec config и AVC NAL envelopes. Внешние media references, fragmented MP4 и другие кодеки/контейнеры не входят в профиль. Это структурная проверка без собственного декодера кадров; успешный импорт не гарантирует воспроизведение каждого кадра любым браузером. Скрытой конвертации нет.

Прямой HTTP(S) URL не должен перенаправлять или возвращать страницу. Доступное вложение из чата импортируется как локальный путь; реальный транспорт вложений из чата здесь не проверен. Оригиналы не меняются, копии получают уникальные имена в `media/`. До сохранения/доставки повторно проверяются путь, SHA256, содержимое и параметры media; symlinks и выход из media запрещены.

Одиночные изображения и плитки сохраняют пропорции без crop; коллаж приблизителен. Слайд-шоу: предыдущий/следующий, счётчик, стрелки/Home/End. Видео: нативные controls, `preload=metadata`, без autoplay, локальная ссылка исходного файла при ошибке; при уходе от слайда/поста видео ставится на паузу. HTTP-сервер отдаёт allowlisted MP4 как `video/mp4` с HEAD и single byte Range; неверный диапазон даёт 416. Внешние медиа не загружаются. Итоговый вид и custom emoji подтверждаются человеком в Telegram после отдельного разрешения доставки.

`load_text("текст")` читает буквальную строку. `load_text(Path("file.txt"))` либо `load_text("file.txt", from_file=True)` читает явно указанный UTF-8 файл до 2 MiB. Автоматической трактовки текста как пути нет.

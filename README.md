# Telegram Rich Messages

Локальный инструмент для подготовки Rich Messages с текстом, изображениями, MP4, коллажами, слайд-шоу, цитатами, раскрывающимися блоками и URL-кнопками. Агент оформляет материал, сохраняет версии и открывает HTML-дашборд. Отправка и изменение сообщения требуют отдельного разрешения конкретной версии в конкретный чат.

Python 3.11 или новее, только стандартная библиотека. Установка пакетов не нужна. Подходит для Codex, Claude Code, OpenCode, Antigravity и других агентных сред с доступом к файлам и терминалу. Конкретная модель и платная подписка не требуются самим проектом; условия выбранной среды определяет её поставщик.

## Для чего этот инструмент

Вы говорите агенту обычными словами, например: «Возьми этот текст и файлы. Обложку первой, затем видео. Последний абзац сделай цитатой. Покажи превью». Агент готовит Rich Markdown, сохраняет версию и открывает результат. Затем можно сказать: «Поменяй изображения местами» или «Этот фрагмент выдели жирным». Синтаксис Markdown и команды терминала знать не нужно. Голосовой ввод предоставляет ваша агентная среда; в самом дашборде микрофона и текстового редактора нет.

Подготовка и просмотр не отправляют пост. Публикация выполняется после явного разрешения конкретной версии и назначения. Обычные emoji сохраняются; для custom emoji нужен точный Telegram ID, удобный каталог пакетов ещё не реализован.

## Что готово, что будет следующим

Сейчас работают локальные черновики и версии, PNG/JPEG/MP4, коллажи и слайд-шоу, цитаты, выделения, emoji, превью и история, непосредственная отправка/правка через бота с защитой от повторов. HTML-превью приблизительное; окончательный вид проверяется в Telegram.

**Текущая версия — личный сервис без отложенных постов.** Основной сценарий: подготовить материал → посмотреть превью → внести правки → разрешить непосредственную публикацию → проверить результат в Telegram. Компьютер нужен во время подготовки и отправки; после подтверждённой отправки пост хранится в Telegram.

Отложка перенесена в [план развития](docs/ROADMAP.md). Проверенный сценарий Controller Bot принимает обычный текст и пересланный обычный пост, но не добавил наш Rich Message в редактор. Протокол и границы вывода — в [результатах проверки](docs/controller-bot-check.md). Экспериментальные записи и receipts сохранены для восстановления; новые `schedule-review`/`schedule-execute` отключены до сети и чтения токена. У постов без прежних операций раздел отложки не показывается.

После приёмки непосредственной публикации следующий этап — публикация открытого репозитория на GitHub и проверка с позиции нового пользователя. Человек присылает ссылку в новый чат; агент по документам репозитория, без прежней переписки, проводит настройку и объясняет подготовку, просмотр, правки и согласование публикации. Прямая тестовая публикация и её вид в Telegram подтверждены пользователем; playback видео отдельно не подтверждён. Приёмка из чистого clone/ZIP и native Windows ещё впереди. Исходный репозиторий — [DjEugeny/telegram-rich-messages](https://github.com/DjEugeny/telegram-rich-messages).

В начале настройки агент предлагает два независимых выбора: подключить существующий канал или создать новый; использовать существующего бота или создать нового. Уже выбранные канал и бот не требуют замены. Создание выполняется только по выбранной человеком ветке; токен человек вводит скрыто в своём терминале.

Целевой сценарий Ольги — её существующий публичный канал, где автор публикации отображается каналом. Текущая проверка использует отдельные тестовый канал и бот; она не доказывает готовность рабочего канала. Отображение автора также проверяется в Telegram.

## Первый запуск

Откройте [репозиторий проекта](https://github.com/DjEugeny/telegram-rich-messages), скачайте ZIP через **Code → Download ZIP** и распакуйте архив. Либо выполните `git clone https://github.com/DjEugeny/telegram-rich-messages.git`. Откройте папку проекта в своей агентной среде и напишите:

> Помоги запустить этот проект.

Агент читает этот файл, [AGENTS.md](AGENTS.md), [ONBOARDING.md](ONBOARDING.md), [HANDOFF.md](HANDOFF.md), выясняет выбранные канал и бот, проверяет Python и сначала показывает локальную демонстрацию без токена. Можно начать с одной ссылки в новом чате: агент помогает получить проект и открыть его папку, затем ведёт по настройке шаг за шагом.

Перед командами агент определяет ОС, shell и фактическую папку запуска проекта и показывает только подходящую вам ветку. Пути ниже — примеры: агент подставляет вашу папку. Если Codex работает удалённо, в контейнере или WSL, он отделяет эту среду от вашего компьютера и при неоднозначности уточняет, где запускается проект. Скрытый ввод токена и дальнейший CLI должны использовать одну установку проекта и среду. Защищённое хранилище токена реализовано для macOS и Windows; Linux/WSL для доставки сейчас не поддержаны, открытого хранения токена взамен нет.

### macOS: Terminal

Нажмите `Cmd+Space`, введите `Terminal`, нажмите `Enter`. Откроется окно для команд. Копируйте команды по одной строке и нажимайте `Enter` после каждой.

Сначала перейдите в распакованную папку: введите в Terminal `cd` и пробел, перетащите папку из Finder в окно Terminal, затем нажмите `Enter`. После этого выполните:

```sh
python3 --version
python3 tool.py demo
python3 tool.py build
python3 tool.py serve --port 8765
```

Если Python отсутствует или старше требуемой версии, установите Python 3.11+ с [официальной страницы Python для macOS](https://www.python.org/downloads/macos/), заново откройте Terminal и повторите проверку. Остановить сервер: `Ctrl+C`.

### Windows: PowerShell

Откройте меню «Пуск», введите `PowerShell` и откройте найденное приложение обычным запуском, без «Запуск от имени администратора». Копируйте команды по одной строке и нажимайте `Enter` после каждой.

Пример, если папка находится в `C:\Проекты\Telegram постинг`:

```powershell
Set-Location -LiteralPath 'C:\Проекты\Telegram постинг'
py -3 --version
py -3 tool.py demo
py -3 tool.py build
py -3 tool.py serve --port 8765
```

Если `py` отсутствует, установите Python 3.11+ с [официальной страницы Python для Windows](https://www.python.org/downloads/windows/), включите установку launcher и заново откройте PowerShell. Если доступна только команда `python`, проверьте `python --version` и используйте её вместо `py -3`. Менять ExecutionPolicy и запускать PowerShell от администратора не нужно.

После подготовки агент сам открывает дашборд доступным браузерным инструментом. Резервный вариант: открыть [локальный дашборд](http://127.0.0.1:8765/). Без сервера откройте файл `index.html` в распакованной папке проекта двойным щелчком. Если автоматическое открытие невозможно, агент выдаёт точный абсолютный путь в вашей установке.

Демо вымышленное, содержит изображение, раскрывающийся блок и ссылку. Повторный `demo` не должен создавать дубликаты. В интерфейсе нет кнопки отправки. Подпись превью: «Приблизительный предпросмотр. Итоговый вид проверь в Telegram».

Для четырёх дополнительных вымышленных примеров выполните `python3 tool.py demo-media`, затем `python3 tool.py build` (Windows: `py -3`). Это шесть портретов 4:5; один портрет 3:4; видео и три портрета 9:16 с цитатой и emoji; портрет 4:5 с цитатой. Встроенный видеофайл — H.264 96×160, одна секунда. Повторный запуск не меняет существующие примеры и их версии. Сеть, токен и ffmpeg не нужны. В примере custom emoji используется вымышленный ID; его работоспособность в Telegram не подтверждена.

## Первая публикация

1. Посмотрите демо; можно остановиться на черновике.
2. Выберите существующий канал или создание нового; отдельно — существующего бота или нового через [BotFather](https://t.me/BotFather). Создавайте только то, что выбрали. Добавьте выбранного бота в целевой канал или группу, выдайте нужные права публикации, изображений, видео и редактирования.
3. **Самостоятельно** выполните `token-set` по одной подходящей инструкции агента: на macOS откройте «Терминал» через `Cmd+Space`, перейдите командой `cd` в фактическую папку проекта и запустите `python3 tool.py token-set`; на Windows откройте PowerShell через «Пуск», перейдите командой `Set-Location -LiteralPath` в свою папку и запустите `py -3 tool.py token-set`. По запросу скрытого ввода вставьте токен из BotFather (`Cmd+V` на Mac, `Ctrl+V` в PowerShell), нажмите `Enter`. Символы не отображаются. ExecutionPolicy менять не нужно. Не отправляйте токен агенту, в чат, аргументы команды или скриншот.
4. Передайте агенту точный `@username` публичного чата либо проверенный числовой ID и при необходимости ID темы. Агент проверяет бота, чат и права через `check`.
5. Дайте текст и медиа. Агент копирует файлы в `media/`, сохраняет версию и открывает дашборд.
6. Агент выполняет `review`, показывает версию, бота, чат, тему и действие. После вашего явного разрешения именно этой версии выполняет `execute`.
7. Проверьте результат в Telegram и сообщите агенту. Только после этого фиксируется визуальная проверка.

Само по себе «подготовь пост» разрешает подготовку. Для отправки нужен запрос вида «Опубликуй пост … версии … в …». Для правки опубликованного сообщения согласуются новая версия, тот же чат и `message_id`.

## Повседневная работа

Пишите агенту: «Подготовь пост из этого текста, изображение по пути …», «Покажи историю за месяц», «Измени этот черновик», «Открой дашборд». Смысл, факты и авторский тон сохраняются; существенное переписывание обсуждается. Таблицы — по запросу или когда нужны данным. Если назначение текста неясно, агент уточняет: «Это текст для поста в Telegram?».

Команды текущего сценария: `demo`, `demo-media`, `create`, `import`, `update`, `list`, `show`, `build`, `serve`, `check`, `discover`, `review`, `execute`, `recover`, `resolve`, `verify-visual`, `token-set`. Обычные действия выполняет агент по [ONBOARDING.md](ONBOARDING.md). `schedule-*` оставлены для истории эксперимента и восстановления, не для новой постановки. Справка — `python3 tool.py COMMAND --help`; в PowerShell — `py -3`. Другой корень: `python3 tool.py --root "/путь с пробелами/проект" build`.

Обычные команды выполняет агент. Ручной ввод нужен для `token-set`; остальные команды ниже — справка и резервный способ самостоятельной работы:

```sh
python3 tool.py create --title "Новый пост" --text "Текст для черновика"
python3 tool.py create --title "Пост из файла" --file "/путь с пробелами/текст.txt"
python3 tool.py create --title "Медиа над текстом" --text "Текст" --video "/путь/ролик.mp4" --image "/путь/портрет.png" --media-layout collage
python3 tool.py create --title "Листаем изображения" --text "Текст" --media "/путь/первое.jpg" --media "/путь/второе.png" --media-layout slideshow
python3 tool.py list
python3 tool.py show POST_ID
python3 tool.py update POST_ID --text "Исправленный текст"
python3 tool.py update POST_ID --blocks "/путь с пробелами/блоки.json"
```

В командах `show`/`update` агент подставляет настоящий `POST_ID` из результата создания. Эти действия сохраняют локальный материал; отправка требует отдельного разрешения.

`--media`, `--image` и `--video` повторяются и сохраняют общий порядок аргументов, в том числе при смешивании. `--media` определяет формат; `--image` принимает только PNG/JPEG, `--video` только поддерживаемый MP4. Один файл становится одиночным блоком, несколько — `collage` по умолчанию. `--media-layout separate` сохраняет отдельные блоки. Новые файлы по умолчанию идут перед текстом; `--media-position after` ставит их после заданных блоков. Полный порядок, цитаты и custom emoji задаются через `--blocks`: [команды и канонический JSON](examples/README.md).

`update POST_ID --media …` без нового текста/JSON добавляет файлы к сохранённым блокам. `--text` или `--file` задаёт новый набор текстовых блоков; для изменения текста с сохранением прежних медиа передайте полный `--blocks`. Изменение порядка и оформления создаёт новую версию и требует нового review перед доставкой.

## Хранение и перенос

`posts/` хранит исходники и экспорты версий; `media/` — локальные копии изображений и MP4; `data/` — SQLite, настройки и журнал. `index.html` генерируется заново. Исходные файлы не меняются. Токен хранится отдельно: macOS Keychain либо Windows DPAPI с ACL текущего пользователя.

Переносите папку проекта вместе с `posts/`, `media/`, `data/` при остановленных операциях. На новом компьютере заново введите токен через `token-set`: Keychain не входит в папку, DPAPI привязан к пользователю/системе. Сохранённые `message_id` и неизвестные результаты сохраняйте: перенос не разрешает повторную отправку. Сначала `recover`, затем `build` и проверка назначения.

Пользовательские данные, `secrets/`, `config.local.json` и HTML исключены из Git. Пустой `config.example.json` не содержит настроек пользователя. Не публикуйте каталог с личными материалами как архив для общего доступа.

## Ограничения

v1 принимает изображения до 10 MiB: PNG без interlace и JPEG 8-bit baseline grayscale/RGB с Huffman-кодированием. PNG с interlace и JPEG progressive, lossless или arithmetic явно отклоняются. MP4 — до 50 MiB, nonfragmented ISO-BMFF, один H.264/AVC `avc1` видеотрек и необязательный AAC `mp4a` аудиотрек. HEVC/H.265, AV1, WebM, MOV и fragmented MP4 не входят в заявленный профиль. Проверка контейнера и таблиц samples не декодирует каждый кадр. При отказе экспортируйте копию в поддерживаемом варианте; скрытой конвертации нет. Подробности — в [examples/README.md](examples/README.md).

Вложение доступно агенту только как реальный локальный файл. Прямой HTTP(S) URL должен вести к поддерживаемому файлу, без редиректов и страниц. Отложенная публикация исключена из текущей версии; перенос и отмена не поддержаны. Нет CMS, обхода сайтов, callbacks и встроенной модели. Поддерживается только Rich Message; классические `sendPhoto`/`sendMediaGroup` не добавлены.

HTML-превью приблизительное: пропорции и порядок сохраняются, мозаика может отличаться от Telegram. Слайд-шоу листается кнопками и клавиатурой, видео использует нативные controls; при уходе от поста/слайда воспроизведение останавливается. Оригиналы доступны по локальной ссылке. Обычные Unicode emoji сохраняются как текст. Custom emoji задаётся явным ID и fallback-символом, локально показывается этим символом без загрузки анимации; доступность боту и итоговый вид проверяются отдельно в Telegram.

При таймауте результат может быть `unknown`: автоматический повтор запрещён. Подтверждённый `message_id` означает успех API, даже если обновление HTML не удалось. Инструкции восстановления — в [ONBOARDING.md](ONBOARDING.md). Реальные отправка/правка и проверка в Windows требуют отдельных проверок; текущие факты — в [HANDOFF.md](HANDOFF.md).
